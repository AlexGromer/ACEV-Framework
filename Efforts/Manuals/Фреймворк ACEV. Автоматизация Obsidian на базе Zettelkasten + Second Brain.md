### Контент 

#### Описание фреймворка
Фреймворк называется ACEV по буквам входящих в него каталогов. Это каталоги:
- Archive - архивные записи, например, архивы проектов, информация по которым может пригодиться или быть использована в будущем (например, резюме), но имеет специфический, привязанный к проекту, характер. Например, конкретный конфигурационный файл микросервиса в конкретной системе. Каталог имеет плоскую структуру.
- Atlas - здесь производится индексация и сбор ссылок в виде таблиц с данными каждой отдельной записи. Atlas состоит из файлов MoC (Map of Content), который представляет из себя "карту темы", которой он посвящен. MoC является узлом связи для всех заметок, имеющих одну общую тему (свойство файла: Тема), также это ссылочный узел, то есть, все записи с указанным свойством Тема указывают на конкретный MoC, поэтому свойство Тема в заметке всегда wiki-ссылка. Также это помогает строить связи на графе. В каталоге Atlas также лежит MoC Index. Этот MoC собирает индекс по всем MoC, то есть, это индекс карт для удобства перехода к нужному MoC. В основе MoC лежит Dataview плагин, MoC собирается автоматически. MoC - часть реализации методологии Second Brain. Каталог имеет плоскую структуру.
- Calendar - в этом каталоге хранятся ежедневные календарные заметки. Для них не предусмотрен MoC и индекс, названия должны быть в виде соответствующих дат. Каталог имеет двухуровневую вложенность. 1 уровень - год, 2 уровень - месяц. Даты в виде отдельных заметок.
- Cards - это карточки с атомарными записями (одна запись - одна идея), создающимися по методике Zettelkasten. Для этих карточек не подразумевается автоматическое выявление связанных записей в конце заметки с помощью DataView, так как Zettelkasten подразумевает ручное установление связей между объектами с целью повышения качества запоминания и стимулирования творческого процесса при разработке новых идей. Карточки пишутся своими словами, раскрывают одно понятие, затем с помощью wiki ссылок устанавливается узловая связь с другими понятиями. Каталог имеет плоскую структуру.
- Efforts (Усилия) - это каталог с черновиками и пробными версиями уже сформированных статей базы знаний, включающими информацию из карточек (Cards) не в атомарном, а в связанном виде. Они больше по объёму, имеют незаконченный вид. Здесь проводятся исследования и разработки, также доработки (новые версии) уже готовых статей. Заметки из этого каталога в своей структуре имеют автособираемые индексы связанных заметок по свойству Подтема, которое не является узловым свойством. Также можно создавать ручные связи через wiki ссылки в соответствующем разделе. Каталог имеет 1 уровень вложенности. Внутри каталога находятся проработанные мной ранее каталоги по областям (domains, realms), они имеют плоскую структуру.
- Vaults (Хранилища) - аналогично Efforts, но тут уже законченные частицы знаний.
- Templates - каталог, содержащий шаблоны всех типов для плагина Templater.
	- Base Template - шаблон Efforts
	- Calendar Template - шаблон Calendar
	- Card Template - шаблон карточки
	- MOC Index Template - шаблон индекс MoC
	- MOC Template - шаблон MoC
	- Vault Template - шаблон Vaults
- Scripts - каталог с пользовательскими скриптами и хуками.
	- uuid.js - скрипт генерации uuid для шаблонов
	- FolderSyncHook.md - стартовый хук для Templater, который автоматически проставляет свойство "Группа" для заметки в зависимости от каталога, в котором находится заметка, а также проставляет порядковый номер в группе для этой заметки.

#### Жизненный цикл заметки и правила использования 
1. Когда необходимо создать заметку, заметка создаётся в любом каталоге. Исключение составляет календарная заметка, для неё лучше сразу создавать недостающие каталоги (год и месяц) и создавать заметку там.
2. После создания вводится название заметки. Название заметки должно быть уникальным в пределах всей системы.
3. После ввода названия курсор переводится в тело заметки. Затем с помощью сочетания клавиш Ctrl+P вызывается палитра. В ней по ключевому слову Templater находится опция Tepmlater: Open Insert Template modal. После выбора данной опции выбирается тип шаблона.
4. После выбора типа шаблона заметка автоматически наполняется базовой структурой. Шаблоны автоматически проставляют id, группу, порядковый номер в группе, название, структуру, связи с помощью Dataview (сам запрос, который обновляет содержимое автоматически, когда вы проставите свойства Тема и Подтема), тег (частично для Efforts и Vaults, полностью для всех остальных. Исключение - календарная заметка) и переводит курсов в следующее заполняемое вручную место.
5. Вы проставляете тему в виде wiki ссылки. Если тема новая, то затем нужно будет кликнуть на ссылку и создать соответствующий MoC, воспользовавшись шаблоном MOC Template по том же принципу, что описан в этом разделе.
6. Вы проставляете подтему.
7. Вы заполняете заметку.
8. Вы выстраиваете связи при необходимости.
9. В конце вы проставляете теги. Первый тег должен соответствовать группе, к которой относится заметка. Для Cards, и Atlas тег в шаблонах существует полный. для Efforts: Efforts/, для Vaults: Vaults/. Вы дописываете группу самостоятельно в этот тег. 
10. Когда вы дополните первый тег, плагин Auto Note Mover автоматически разместит файл в каталоге группы. Группа и порядковый номер обновятся автоматически.
11. Остальные теги вы проставляете на своё усмотрение.
12. Заметки Second Brain всегда сначала создаются в Efforts в соответствующей группе. После завершения работы и признания заметки законченной ей проставляется тег с Vaults, чтобы переместить автоматически, либо производится удаление тега, ручной перенос и добавление нового тега.
13. Новые правила размещения можно добавлять в настройках плагина Auto Not Mover.
14. Заметки не удаляются, только модернизируются. 
15. Устаревшие заметки, если их содержимое уже не принадлежит к существующим активностям или не будет дорабатываться, переносятся в архив. 
16. Работа с Second Brain может начинаться с любого сценария. Например, вы сделали ежедневную заметку, выделили какую-то мысль, разместили её в Zettelkasten, связали с другими мыслями. У вас родилась идея исследования по связанным заметкам, вы создали заметку в Efforts, связались с ней предыдущие заметки. Провели работу, например, в течении месяца, оформили страницу знаний, пометили её законченной, переместили в Vaults.

**Жизненный цикл Archive**
Заметка в Efforts, Cards или в Vaults устарела и не будет дорабатываться -Поступление в Archive - Периодическое повторение (просмотр) - возможное восстановление в других каталогах
**Жизненный цикл Atlas**
Создана заметка - создан MoC - MoC обновляется автоматически
**Жизненный цикл Calendar**
Создана календарная заметка - заметка разобрана на атомарные концепции (при необходимости) - создан черновик (при необходимости) - собрана статистика по статистическим показателям из заметки - проделаны вывод - заметки старше 3 лет архивируются - календарные заметки периодически просматриваются
**Жизненный цикл Cards** 
Создана атомарная заметка Zettelkasten - построены связи с другими заметками - заметка добавлена в периодическое повторение - заметка устарела - заметка перемещена в архив
**Жизненный цикл Efforts**
Создана страница знаний Second Brain - построены связи с другими заметками - проставлена версия - заметка добавлена в периодическое повторение - если заметка дорабатывается и завершается, то перемещение в Vaults - если заметка устаревает до завершение - перемещение в архив
**Жизненный цикл Vaults**
Заметка перемещена из Efforts - если заметка копируется из готового источника, то заметка создана - заметка добавлена в периодическое повторение - если заметка устарела и может быть доработана, новая версия создаётся в Efforts или текущая версия перемещается в Efforts для доработки - заметка устарела - заметка перемещена в архив

**Ручные связи**

**Связанные записи по теме:** 
```dataview 
TABLE WITHOUT ID
	"Порядковый номер в группе" AS "№",
	id AS "ID",
    Подтема AS "Подтема",
    file.link AS "Название",
    Группа AS "Группа",
    "Дата создания" AS "Дата создания"
FROM "Efforts" OR "Cards" OR "Archive"
WHERE Тема = this.Тема 
AND Тема != null
AND Подтема = this.Подтема
AND Подтема != null 
AND file.path != this.file.path 
```
